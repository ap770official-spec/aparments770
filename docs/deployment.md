# פריסה חיה (Deployment)

## כתובת האתר החי

```
https://aparments770.vercel.app
```

זו סביבת **בדיקה/פיתוח** — לא מודעת/מקושרת לשום מקום ציבורי, לא מאונדקסת בגוגל.
עדיין לא מחובר אליה דומיין אמיתי.

## איך זה מחובר

- **Vercel** מחובר ישירות ל-GitHub, לענף `claude/apartments770-basic-setup-oqzbfi`.
- כל `git push` לענף הזה מפעיל אוטומטית build+deploy חדש ב-Vercel, בלי צורך בפעולה ידנית.
- ששת משתני הסביבה (Supabase, Mapbox, Cloudinary) מוגדרים ישירות בהגדרות הפרויקט ב-Vercel
  (Project Settings → Environment Variables), בנפרד מ-`.env.local` המקומי.
  אם ערך משתנה (למשל אחרי rotation של מפתח) — צריך לעדכן גם שם, לא רק ב-`.env.local`.

## למה זה קיים (ולמה מוקדם מהמתוכנן)

הסביבה שבה Claude עובד על הפרויקט הזה חסומה מגישה לאינטרנט החיצוני מלבד כמה כתובות
ספציפיות (לא כולל Supabase, Mapbox, Cloudinary או אפילו `vercel.app` עצמו). המשמעות:
Claude יכול לכתוב קוד שמתחבר לשירותים האלה, ולוודא שהוא מתקמפל בלי שגיאות — אבל
**לא יכול לבדוק בעצמו שהחיבורים האמיתיים עובדים**.

בגלל זה הועברה הפריסה ל-Vercel הרבה יותר מוקדם מהתכנון המקורי (שם היא הייתה שלב אחרון).

## איך בודקים תכונה חדשה מעכשיו

1. Claude בונה את התכונה, מוודא build/lint נקיים, ודוחף ל-GitHub.
2. Vercel בונה ופורס אוטומטית לכתובת למעלה (לוקח כדקה-שתיים).
3. פותחים את הכתובת בדפדפן (או ישירות דרך `/he` / `/en` לעמוד ספציפי), ומדווחים
   ל-Claude מה רואים — טקסט, צילום מסך, או תיאור של שגיאה.

זו הדרך היחידה כרגע לוודא שקוד שנוגע ב-Supabase/Mapbox/Cloudinary באמת עובד, לא רק
"נראה נכון".
