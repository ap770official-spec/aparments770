## מה המטרה

כרגע (`src/components/SearchForm.tsx`) תאריך כניסה ותאריך יציאה הם שני שדות
`<input type="date">` נפרדים ורגילים של הדפדפן — בלי שום קשר ביניהם, ובלי שום
מידע על חגים. הוחלט:

1. **תאריכים נשארים לועזיים** (לא עוברים ללוח עברי — זו הייתה שאלה שנשאלה
   במפורש ונענתה: לא לשנות את מערכת התאריכים עצמה).
2. אבל **לסמן חגים/מועדים יהודיים** על גבי הלוח (כמו שאפליקציות טיסות מסמנות
   ימים מיוחדים) — כדי שמי שמזמין דירה יראה בבירור אם הוא נוחת בתוך חג.
3. **זרימת בחירה כמו הזמנת כרטיס טיסה**: לוח שנה אחד (לא שני שדות נפרדים) —
   לוחצים על תאריך כניסה, והלוח עובר אוטומטית למצב "עכשיו תבחר תאריך יציאה"
   (בלי לסגור/לפתוח דו-שיח בנפרד, בלי להקליד תאריך ידנית).

זה חל על **טופס החיפוש הציבורי בלבד** (`SearchForm.tsx`, בדף הבית). לא לגעת
בשדות `checkin_time`/`checkout_time` בטופס פרסום דירה (`PropertyForm.tsx`) —
אלה שעות, לא תאריכים, נושא נפרד לגמרי.

## מה לבנות

### 1. ספריית לוח שנה
אין כרגע שום ספריית date-picker בפרויקט (`package.json` נבדק). מומלץ:
`react-day-picker` (תומך RTL, תומך "range mode" מובנה בדיוק בהתנהגות
המבוקשת — קליק ראשון = start, קליק שני = end, סוגר את הבחירה אוטומטית).
תואם ל-React 19 / Next.js 16 שכבר בפרויקט.

```
npm install react-day-picker
```

### 2. מקור נתוני החגים
מומלץ `@hebcal/core` — ספריית החישוב הרשמית של Hebcal, מחשבת תאריכי חגים
עבריים באופן מקומי (בלי קריאת רשת בזמן ריצה, בלי תלות בשירות חיצוני). לחשב
את רשימת החגים לכל טווח השנים הרלוונטי (למשל השנה הנוכחית + הבאה) ולסמן
אותם כ-`modifiers` על הלוח.

```
npm install @hebcal/core
```

חגים לסמן (לפחות): ראש השנה, יום כיפור, סוכות (כולל חול המועד ושמחת תורה),
פסח (כולל חול המועד), שבועות, ל"ג בעומר, פורים, חנוכה, תשעה באב. כל יום
מסומן מקבל צבע/רקע ייחודי + tooltip או תווית קטנה עם שם החג (בעברית/אנגלית
לפי השפה הפעילה באתר — `next-intl`, `useTranslations`).

### 3. שינוי `SearchForm.tsx`
- להחליף את שני שדות `<input type="date">` (checkin/checkout) ברכיב לוח שנה
  יחיד במצב range, שמציג את שני החודשים (או חודש אחד, לפי מה שנראה טוב
  ב-RTL) ומאפשר את זרימת הבחירה שתוארה למעלה.
- לשמור את אותו ה-state הסופי (`checkin`, `checkout` כ-strings בפורמט
  שה-query params של `/search` כבר מצפים לו) — לא לשנות את מבנה ה-URL
  שנשלח הלאה, רק את חוויית הבחירה.
- הלוח חייב לעבוד גם בעברית (RTL) וגם באנגלית (LTR) — שתי השפות הנתמכות
  באתר (`messages/he.json`, `messages/en.json`) — כולל שמות חודשים/ימים
  בשפה הנכונה.
- לוודא שהעיצוב עקבי עם שאר האתר (Tailwind v4, מצב כהה/בהיר קיים כבר בקוד —
  ראו איך `dark:` classes משמשות בקבצים אחרים).

### 4. מה לא לשנות
- לא לגעת ב-`PropertyForm.tsx` (טופס פרסום דירה) — אין שם בקשה לשינוי.
- לא לשנות את מבנה מסד הנתונים או את ה-query params שנשלחים ל-`/search`.
- לא להחליף את התאריכים עצמם ללוח עברי — רק לסמן חגים על גבי הלוח הלועזי.

## בדיקת קבלה (לפני push)
1. `npm run lint` ו-`npm run build` עוברים נקי.
2. בדף הבית: לוח שנה אחד מופיע במקום שני שדות תאריך נפרדים.
3. קליק על תאריך כניסה עובר אוטומטית לבחירת תאריך יציאה, בלי צעד ידני נוסף.
4. חגים יהודיים מסומנים ויזואלית על הלוח (למשל רקע צבעוני), עם שם החג נגיש
   (tooltip/תווית) — לבדוק לפחות חג אחד מהשנה הקרובה.
5. עובד גם ב-`/he` וגם ב-`/en`.
6. שליחת הטופס עדיין מגיעה לדף `/search` עם `checkin`/`checkout` תקינים,
   בדיוק כמו היום.
